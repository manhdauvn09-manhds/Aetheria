1. Overview NEW

Aetheria is a free-to-play, turn-based hex-grid strategy RPG built on a TypeScript monorepo. The web client (Next.js 15 + Pixi.js 8) is responsive (mobile + desktop). The server (Fastify + tRPC v10) is server-authoritative for all combat. Production runs on Hetzner Ubuntu 24.04 behind Cloudflare, co-resident with a separate PrivateDatingLevel stack via Docker compose project isolation.

3. Architecture NEW

Monorepo with 4 apps (api / web / realtime / worker) and 20+ domain packages. Each domain (auth, combat, world, quests, social, etc.) exports a Service factory + tRPC sub-router that apps/api composes.

Request flow

Browser → Cloudflare → Caddy (host) → Aetheria container (127.0.0.1:18100/01/02)
   ↓
Next.js / Fastify-tRPC → service layer → Prisma → MySQL 8
                                       → ioredis → Redis 7

Combat loop

Server-authoritative: client predicts, then reconciles with server. Combat state stored as {schemaVersion, state} JSON envelope in runs.snapshot column. Action log replayed against engine seed for integrity check. Optimistic CAS via runs.revision counter prevents race-clobber.

4. Features NEW

4.1 Game world

  • 100 levels organised into 5 realms (Verdant Reach, Ember Wastes, Frostspire, Tideglass, Voidmaw). 13 hand-authored, 87 procedurally generated.
  • 20-position archetype cycle per realm: intro → skirmish → patrol → cache → elite → … → realm-boss (Void Lord).
  • Difficulty scales with level number (1-10 difficulty tiers).

4.2 Heroes

  • 8-character roster: Aevra (DPS), Kyo (Bruiser), Lyra (Mage), Brann (Tank), Mira (Healer), Vex (Assassin), Solen (Support), Null (Wildcard). Role-tuned HP/ATK/DEF/SPD.
  • Vector SVG sprites per archetype, loaded as Pixi textures (fallback to Graphics shapes).
  • Team Builder page: pick 1-3 heroes, persisted to profile.preferences.selectedTeam. Party = selectedTeam ∩ owned heroes (starters always available). Unowned heroes silently dropped + rotation-filled. Resolved party persisted to runs.party_config for deterministic replay.

4.3 Combat

  • 6×4 hex grid → now uses authored level geometry from game-assets (terrain, spawns, exits match map-view). Spawn de-collision guarantees distinct tiles. AP system (3/turn). Element wheel with damage advantage 0.75/1.0/1.25.
  • Actions: Move (multi-step BFS pathfinder client-side, engine validates step adjacency), Attack, Defend, End Turn. Pan/zoom: drag + wheel/pinch + Recenter button on CombatScene canvas.
  • Skills catalog (6): power_strike, firebolt (burn DOT), venom_dart (poison DOT), heal, bulwark (self_buff), bless (ally_buff). Each hero gets role-mapped skills.
  • Status effects active: burn / poison DOT tick on turn boundary (engine turn.tickStatuses). Aether_surge buff for defense.
  • Resonance: +50% AoE damage when 2+ party heroes share element. HUD badge surfaces "armed" state.
  • Server-side enemy AI: chase → attack-if-adjacent → end-turn fallback.
  • Victory/Defeat/Draw modal with HP recap + reward summary + Next Level / Retry CTAs.
  • Mid-combat resume: combat.start returns existing in-progress snapshot instead of rebuilding. Leaving + re-entering /play/[N] preserves fight progress.

4.4 Progression

  • Account XP + gold tracked on profile. Reward grant on victory: profile increment + inventory item upsert inside one transaction. XP now routes through applyAccountXp (recomputes accountLevel + emits LeveledUp milestones). Gold via direct increment. Both inside single $transaction with inventory upserts.
  • Daily + weekly quests (3 + 2 seeded): complete_levels, defeat_enemies, finish_runs. Progress tracked via event bus (LevelCompleted / RunFinished / EnemyDefeated). Claim button → XP grant.

4.5 Mobile

  • Responsive canvas: ResizeObserver-driven sizing. hexSize scales 14-38 px to fit any viewport without horizontal scroll.
  • Pixi perf hints: cap resolution at 2 (avoid hi-DPR fillrate burn), antialias off when navigator.hardwareConcurrency ≤ 4.
  • Tap-friendly: all HUD + action buttons py-2 (~44px target, Apple HIG).
  • touch-none class on canvas wrapper to suppress browser pan/zoom, deferring to Pixi pointer events.

4.6 Audio

  • Procedural Web Audio SFX: attack/crit/heal/buff/defeat/victory/loss/skill/click. No audio assets. Mute toggle 🔊/🔇.

5. API surface (tRPC) NEW

All procedures are HTTPS POST to https://aetheria-api.games-core.com/trpc/<name>?batch=1. Auth procedures additionally wrapped by Next.js /api/auth/* routes that set the httpOnly refresh cookie.

5.1 Auth

  • auth.signupWithEmail — signup with HIBP password breach check, enumeration-resistant conflict message
  • auth.loginWithEmail
  • auth.refreshToken — reuse detection: invalid JTI → revoke ALL user sessions (OWASP)
  • auth.logout
  • auth.requestPasswordReset / confirmPasswordReset — HIBP check on new password
  • auth.requestEmailVerification / confirmEmailVerification — timing-safe token compare

5.2 Account

  • account.getProfile · account.updateProfile (preferences.selectedTeam, avatarUrl whitelist, 8KB cap)
  • account.getLeaderboard

5.3 World

  • world.realms · world.levelsForRealm (merges DB rows + game-assets fallback)
  • world.startLevel (auto-upserts levels row for FK resolution)
  • world.resumeRun · world.abandonRun

5.4 Combat

  • combat.start — synthesises 3-hero party from selectedTeam or rotation; 2 enemies non-boss, 1 Void Lord on lvl%20==0
  • combat.submitAction — validates skill ∈ catalog AND ∈ actor.skills; CAS write; reward grant on victory
  • combat.replay

5.5 Other domains

7. Security NEW

  • Argon2id password hashing. JWT (jose) access (15-min) + refresh (30-day) with rotation + reuse detection.
  • HIBP k-anonymity password breach check at signup + reset (soft-fail on network errors).
  • Rate-limit: global 100/min/IP + auth-specific 10/60s/IP (Redis-backed).
  • ENFORCE_CLOUDFLARE=false (after Caddy CF header forwarding fix).
  • Helmet: CSP default-src 'none' on API; script-src 'self' 'unsafe-eval' on web (Pixi v8 requirement, documented trade-off).
  • SSRF guard on avatarUrl: scheme whitelist (https-only), private-IP block.
  • Preferences payload 8KB cap. Combat snapshot CAS + replay-hash integrity.
  • User enumeration mitigation: signup unifies conflict cases to single generic 409 + constant-time lookups. HIBP k-anonymity password breach check at signup + reset (soft-fail on network).
  • consoleMailer REFUSES to log in production (would leak reset tokens to stderr).
  • .env.prod permissions 0600. fail2ban + Hetzner Cloud Firewall (operator IP whitelist only on :22).

8. Operations NEW

  • Compose project: aetheria-prod (isolated docker network from PLD pld-prod).
  • Host ports: 127.0.0.1:18100 (web), :18101 (api), :18102 (realtime). Caddy reverse-proxies on :443 with CF Origin CA cert.
  • URL pattern: dash naming (aetheria-api.games-core.com) — CF Free wildcard supports 1 level only.
  • Backup: MySQL nightly dump at 03:15 UTC, 14-day retention at /var/backups/aetheria/mysql/.
  • Test suite: scripts/test/run-all.ps1 — 110+ cases across 10 suites (infra / security / auth / account / world / save / realtime / misc-tRPC / URL-pattern / combat-playthrough).
  • Deploy: scp source → docker compose build api web → up -d. PLD untouched (different compose project).
