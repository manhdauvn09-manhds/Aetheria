1. Project Overview

What is Aetheria?

Aetheria is a free-to-play, turn-based hex-grid strategy RPG with real-time exploration and live PvP. Players explore floating islands, discover lore, build teams of heroes, battle monsters and rivals, and compete on global leaderboards.

Key Facts

  • Repository: E:\SourceCode\aetheria (GitHub: manhdauvn09-manhds/Aetheria)
  • Active Branch: claude/create-project-structure-3uMmU
  • Status: Production-ready (stable, tests passing, ops reliable)
  • Monorepo: pnpm workspaces (4 apps, 20+ packages)
  • Language: 100% TypeScript

Game Concept

A thousand years after the Aether shattered into seven Shards, the realm of Aetheria drifts apart on floating islands. Heroes of the Aetherbound must explore lost continents, reclaim the Shards, outwit rival factions, and master the broken sky before the Void devours what remains.

Core Loop

Explore → Discover → Strategize → Battle → Loot → Level up → Compete

Game Design Pillars

  1. Discovery is reward — every level hides secrets (lore, rare items, hidden bosses)
  2. Mastery, not grinding — clever party composition & terrain use beat raw stats
  3. Always saved, always returnable — auto-save mid-action; resume anywhere
  4. Social by default — global ranking, guilds, co-op raids, seasonal tournaments

Combat System

  • Grid-based hex combat on 6×8 hex maps with elevation & elemental tiles
  • Action Points (AP): 3/turn; movement, attack, skills consume AP
  • Elements: Verdant, Ember, Frost, Tide, Sky, Void (weak/strong wheel)
  • Status Effects: Burn, Freeze, Poison, Stagger, Aether-Surge
  • Resonance: Two characters matching elements trigger combo (+50% dmg, AoE)
  • Turn-based with client-side prediction + server validation

Progression System

  • Account level: 1–100 (mirrors campaign)
  • Character ascension: A0–A3 (gear + Aether-cores)
  • Skill tree: Each character has 12 respec-able nodes
  • Loot tiers: Common → Rare → Epic → Mythic → Aether-Forged
  • Crafting: Combine duplicates + shards to upgrade

Online & Social Features

  • Account system: Email + OAuth (Google, Discord); JWT sessions
  • Cloud save: Every action snapshotted; offline edits reconciled on reconnect
  • Leaderboards: Global, Regional, Guild, Friends
  • Ranked PvP: Bronze→Mythic, seasonal reset
  • Guilds: Up to 30 members; guild raids weekly
  • Co-op: 3-player synchronous raids (WebSocket)
  • Marketplace: Soft-currency only; no pay-to-win
  • Chat: Global, party, guild, whisper; profanity filter + report

Engagement Hooks

5. Domain Packages Architecture

The backend uses a domain-driven design with clear separation of concerns. Each domain is a self-contained package with its own service, router, and repository layer.

Core Domains

domain-auth
Authentication, JWT token management, OAuth (Google, Discord), password reset, email verification. Manages login flows and session lifecycle.
domain-account
User profiles, display names, account level, XP, currency (gold/aether), preferences, settings. Handles profile mutations and leveling.
domain-roster
Character collection management. User character ownership, ascension, XP, skill assignments. Roster viewing and team building.
domain-combat / domain-combat-runtime
Pure combat engine (hexgrid, AP, status, resonance) + runtime service. domain-combat runs client-side for prediction; domain-combat-runtime is the authoritative server validator.
domain-world
World graph, level definitions, encounters, overworld node states, discovery meters. Links to game-assets for level JSON.
domain-save
Cloud save, auto-save, multi-slot saves. Local IndexedDB sync + 30s delta sync. Conflict resolution (server timestamp wins).
domain-inventory / domain-economy
Backpack, equipment, items, loot, crafting, marketplace. Economy rules and item state.
domain-progression
Character XP, ascension, skill trees, level-up mechanics, reward distribution.
domain-quests
Quest state, objectives, progress tracking, rewards. Quest log and completion state.
domain-battlepass
Seasonal battle pass progression, free/premium tracks, cosmetic rewards. Seasonal reset logic.
domain-pvp
PvP matchmaking, leaderboards, MMR rating, match history. Handles ranked seasons and rating decay.
domain-social
Guilds, friendships, chat, messages, moderation. Social graph and messaging system.
domain-notifications
Push notifications, in-game notifications, notification preferences. Event-driven notification dispatch.
domain-shop
In-game shop, cosmetics, battle pass purchase, currency bundles. Shop catalog and transactions.
domain-admin
Admin operations: user bans, role changes, content moderation, audit logs. Privileged operations only.
domain-telemetry
Analytics, event tracking, session recording. Telemetry data collection.

Schema & Utilities

schema-db
Prisma schema (MySQL), type definitions. Single source of truth for database structure.
schema-api
tRPC router base, Zod schemas for all endpoints. Type-safe API definition.
shared-types
Cross-cutting TypeScript types used across all packages.
game-assets
Asset manifest, level definitions (JSON), character catalog. Content platform-independent.
core
Common utilities: RNG, ID generation, error handling, logger setup.

Data Flow: Combat Action

  1. Client: tRPC call combat.applyAction(action)
  2. Fastify: Rate-limit check, JWT verify, Zod schema validate
  3. tRPC Router: Route to createCombatRouter → applyAction
  4. CombatRunService: Load run state from MySQL, lock for atomicity
  5. domain-combat: Pure engine validates action (AP, range, LOS)
  6. Update DB: Write new state to runs table + action_log
  7. Return result: Send updated state, new effects, rewards to client
  8. Client: Apply optimistic update, reconcile if mismatch

Realtime Architecture (Socket.IO)

  • Separate apps/realtime service on port 18102
  • Room per match (PvP) / guild chat channel / global chat
  • Server authoritative: client predicts, then reconciles on server update
  • Heartbeat every 5s; miss >15s → opponent wins by forfeit
  • Sticky sessions on the realtime tier (Redis adapter for horizontal scale)

Save & Cloud-Sync Strategy

  • Two-tier:
    • Local IndexedDB snapshot after every state change (instant resume offline)
    • Server delta sync every 30s or on idle / page-hide
  • Conflict policy: Server timestamp wins; client merges cosmetic (settings, photo album) by union
  • Slots: slot=0 is autosave; slots 1–3 are manual for storyline branching
  • Schema versioning in payload; migration runs on read

Anti-Cheat & Integrity

  • All combat actions validated server-side using same domain-combat package
  • Replay log of every action stored in runs.action_log
  • Worker scans for impossible states (async, scheduled)
  • Rate limits per IP + per user (Redis-backed, returns tRPC 429 envelope)
  • Item/currency mutations only via signed events from server; client never asserts deltas
  • HMAC-signed asset manifest to detect modded clients

Security Baseline

  • HTTPS-only, HSTS, CSP, SameSite=Lax cookies
  • Refresh-token rotation on login
  • Argon2id password hashing
  • OAuth via NextAuth (idP tokens never exposed to API)
  • ENFORCE_CLOUDFLARE=true rejects direct-to-origin requests (403 unless cf-connecting-ip present)
  • Helmet for headers (CSP, X-Frame-Options, X-Content-Type-Options)

Key Endpoints (tRPC Procedures)

auth (Authentication)

  • auth.signup(email, password, displayName) → JWT tokens
  • auth.login(email, password) → JWT tokens
  • auth.oauthCallback(provider, code) → JWT tokens
  • auth.refresh(refreshToken) → New access token
  • auth.logout() → Revoke tokens
  • auth.requestPasswordReset(email) → Send reset link
  • auth.resetPassword(token, newPassword) → Update password

account (Profile & Progression)

  • account.getProfile() → Current user profile
  • account.updateProfile(displayName, avatarUrl, ...) → Mutate profile
  • account.getLeaderboard(type, region) → Global/regional/guild leaderboard
  • account.claimDailyReward() → Daily login bonus

combat (Running Levels)

  • combat.startRun(levelId, partyIds[]) → Initialize combat state
  • combat.applyAction(runId, action) → Execute one action (move/attack/skill)
  • combat.endRun(runId, reason) → Mark run complete/abandoned
  • combat.getRun(runId) → Fetch current run state

roster (Characters & Skills)

  • roster.getCharacters() → User's character collection
  • roster.unlockCharacter(characterId) → Unlock from quest/PvP
  • roster.ascendCharacter(characterId) → Promote A0→A1, etc.
  • roster.assignSkill(userCharacterId, skillId, slot) → Customize skill slots
  • roster.getSkillTree(characterId) → Progression nodes

save (Cloud Saves)

  • save.getSaveState(slot) → Load save (0=auto, 1–3=manual)
  • save.updateSaveState(slot, data) → Write save delta
  • save.getSaveHistory() → List recent saves

world (Levels & Exploration)

  • world.getLevelList() → All 100 levels
  • world.getLevelDetail(levelId) → Full level data + layout
  • world.getRealmProgress(realmId) → Discovery %, completed nodes

pvp (Ranked Battles)

  • pvp.requestMatch() → Enqueue for matchmaking
  • pvp.getMatchState(matchId) → Current match board state
  • pvp.applyMatchAction(matchId, action) → Execute turn in PvP
  • pvp.getLeaderboard(season) → MMR rankings

quests (Objectives)

  • quests.getActiveQuests() → Current objectives
  • quests.claimReward(questId) → Accept completion reward

social (Guild, Friends, Chat)

  • guild.createGuild(name, motd) → New guild
  • guild.getMembers(guildId) → Member list
  • guild.inviteMember(guildId, userId) → Send invite
  • chat.sendMessage(roomId, content, type) → Post to chat
  • chat.getMessages(roomId, limit) → Message history

Error Handling

Critical Convention: All non-2xx responses from /trpc/* paths MUST be tRPC batched envelope format. The web client parses non-tRPC responses as confusing HTTP 500 errors.

tRPC Error Envelope (429 example):

[{
  error: {
    json: {
      message: "Too many requests",
      code: -32029,
      data: {
        code: "TOO_MANY_REQUESTS",
        httpStatus: 429,
        path: "auth.signup"
      }
    }
  }
}]

See apps/api/src/plugins.ts → rateLimitBody() for implementation.

CORS & Headers

  • CORS allowlist must include x-aetheria-client header (set by tRPC browser links)
  • Missing header → Chrome blocks with "Failed to fetch"
  • CF rewrites X-Frame-Options: DENY → SAMEORIGIN on Free plan; both are acceptable

⚡ Auth Flow: Browser → Next.js Routes → tRPC

Critical: Browser does NOT call tRPC directly for auth. It calls Next.js API routes that proxy to tRPC.

Request flow:

Browser POST /api/auth/signup
   ↓
Next.js route handler (apps/web/src/app/api/auth/signup/route.ts)
   ↓ (server-side fetch via apiClient)
tRPC API POST /trpc/auth.signupWithEmail
   ↓
auth.service.signupWithEmail()
   ↓
[user + JWT tokens returned]
   ↓
Next.js sets httpOnly refresh cookie + returns access token JSON
   ↓
Browser receives session

Auth routes (Next.js):

  • /api/auth/signup → wraps auth.signupWithEmail
  • /api/auth/login → wraps auth.loginWithEmail
  • /api/auth/logout → wraps auth.logout
  • /api/auth/refresh → wraps auth.refresh (uses httpOnly cookie)
  • /api/auth/forgot-password → wraps auth.requestPasswordReset
  • /api/auth/reset-password → wraps auth.resetPassword
  • /api/auth/verify-email → wraps auth.verifyEmail

Why wrap:

  • Refresh token never crosses to JS (httpOnly cookie, same-origin)
  • Uniform error envelope (small JSON for React forms)
  • Easier rate limiting at edge

When debugging auth issues, check Next.js logs FIRST: docker logs aetheria_web --tail 50

  • ENFORCE_CLOUDFLARE=true: Rejects direct-to-origin (403 CDN_REQUIRED) unless cf-connecting-ip present
  • Helmet CSP: default-src 'none', JSON-only API hardening
🔴 CRITICAL: Production URL Pattern

Use dash naming, NOT subsubdomains. CF Free plan only supports 1-level wildcard, and using *.aetheria.games-core.com requires DNS entries that don't exist.

✅ CORRECT❌ WRONG
aetheria-api.games-core.comapi.aetheria.games-core.com
aetheria-ws.games-core.comws.aetheria.games-core.com

Symptom of wrong URL: Browser shows "fetch failed" on signup/login. Next.js web container can't resolve NEXT_PUBLIC_API_URL DNS.

11. Critical Development Conventions

🔴 DO NOT SKIP THESE — they prevent silent bugs & production outages

1. tRPC Error Envelope for /trpc/* Paths

All non-2xx responses must return tRPC batched envelope format. Non-tRPC responses confuse the web client into HTTP 500 errors.

// ✅ CORRECT (429 rate limit)
[{ error: { json: { message: "...", code: -32029, data: { code: "TOO_MANY_REQUESTS", ... } } } }]

// ❌ WRONG (web client errors)
{ error: "Too many requests" }  // → HTTP 500 on client
Error              // → Cannot parse JSON

2. CORS Allowlist Must Include x-aetheria-client

tRPC browser links set x-aetheria-client header. Missing → Chrome blocks with "Failed to fetch".

3. MySQL Seed Dependency

db/mysql/02_seed.sql MUST contain 8 placeholder levels rows. FK target for runs.level_id.

-- MUST exist (even with placeholder data)
INSERT INTO levels (id, name, realm, ...) VALUES
  (1, 'Verdant Reach 1', 1, ...),
  (2, 'Verdant Reach 2', 1, ...),
  ...
  (8, 'Verdant Reach 8', 1, ...);

4. fail2ban quirk

ignoreip MUST go inside [sshd] section in /etc/fail2ban/jail.d/*.local. [DEFAULT] blocks in jail.d don't propagate to existing jails.

// ✅ CORRECT
[sshd]
ignoreip = 219.105.121.69

// ❌ WRONG (won't work)
[DEFAULT]
ignoreip = 219.105.121.69

5. CF Rewrites Response Headers

  • X-Frame-Options: DENY → CF makes it SAMEORIGIN on Free plan
  • Both are acceptable; test assertions accept both
  • Real protection is CSP frame-ancestors 'none'

6. DO NOT Add CF Custom Rules

DO NOT use CF Bot Fight Mode, Managed Challenge, or Rate Limiting custom rules. All 3 broke the test suite previously and were rolled back.

7. Prisma binaryTargets for Docker

Must include both native and linux-musl for Alpine compatibility.

binaryTargets = ["native", "linux-musl-openssl-3.0.x"]
// native: Windows/macOS/Linux local dev
// linux-musl: Alpine 3.20+ Docker (Node 22)

8. Use tsx, NOT ts-node

Always use tsx runtime in containers. Node 22 strict ESM doesn't work with ts-node.

// ✅ CORRECT in Dockerfile
CMD ["tsx", "src/index.ts"]

// ❌ WRONG
CMD ["ts-node", "src/index.ts"]  // ESM mode errors

9. pnpm Offline Mode for Docker

Use pnpm fetch then pnpm install --offline in multi-stage builds.

COPY pnpm-lock.yaml .
RUN pnpm fetch --prod
COPY . .
RUN pnpm install --offline --frozen-lockfile

10. Next.js NEXT_PUBLIC_* Baked at Build

NEXT_PUBLIC_* env vars bake into the bundle at build time. Forward via docker-compose.prod.yml build.args + Dockerfile ARG + ENV.

11. API Must Return tRPC Envelope for /trpc/*

Non-2xx from /trpc/* paths MUST be tRPC envelope or client fails. Implement in plugins.ts → rateLimitBody().

12. PowerShell Reserved Words

See section 11 of Session Handoff for Windows PowerShell gotchas.

13. Production URL Pattern — Dash Naming Only

Cloudflare Free plan supports only 1-level wildcard. Use dash naming for subdomains.

// ✅ CORRECT (production)
NEXT_PUBLIC_API_URL=https://aetheria-api.games-core.com
NEXT_PUBLIC_REALTIME_URL=https://aetheria-ws.games-core.com

// ❌ WRONG (DNS doesn't exist → "fetch failed")
NEXT_PUBLIC_API_URL=https://api.aetheria.games-core.com
NEXT_PUBLIC_REALTIME_URL=https://ws.aetheria.games-core.com

After any env change to NEXT_PUBLIC_*, MUST rebuild web container:

cd /opt/apps/aetheria/src
docker compose -p aetheria-prod -f docker-compose.prod.yml --env-file .env.prod build web
docker compose -p aetheria-prod -f docker-compose.prod.yml --env-file .env.prod up -d web

14. Auth Flow: Next.js Routes Wrap tRPC

Browser does NOT call tRPC directly. It calls Next.js API routes that proxy to tRPC server-side. This is for:

  • Refresh token security — never crosses to JS, set as httpOnly cookie
  • Uniform error envelope — React forms render plain JSON errors

Browser → /api/auth/signup → Next.js route handler → apiClient().auth.signupWithEmail.mutate(...) → tRPC API

  • Route handlers: apps/web/src/app/api/auth/{signup,login,logout,refresh,forgot-password,reset-password,verify-email}/route.ts
  • Proxy helpers: apps/web/src/lib/auth/proxy.ts

When debugging "fetch failed" or 500 errors on auth, check Next.js route logs FIRST, not API logs.

15. ENFORCE_CLOUDFLARE Subtleties

ENFORCE_CLOUDFLARE=true rejects requests without cf-connecting-ip header. This breaks:

  • Direct curl from server — bypasses CF, no header
  • Web container → API — IF Caddy doesn't forward header properly

For browser → CF → Caddy → API, the header IS present. Caddy config (/etc/caddy/Caddyfile) must include in API upstream:

(aetheria_api_upstream) {
    reverse_proxy 127.0.0.1:18101 {
        import cf_headers
        header_up CF-Connecting-IP {http.request.header.cf-connecting-ip}
    }
}

Testing locally: Add header manually: curl -H "cf-connecting-ip: 1.1.1.1" ...

13. Known Issues & Traps (Already Solved — Don't Re-Debug)

ℹ These are documented to prevent re-debugging. They're production-ready.
  1. $Input reserved in PowerShell → Helpers use $Payload
  2. Bash heredoc in PowerShell → Use `$ for shell vars, ${Var} for PS vars
  3. CF Free wildcard limit → Use dash naming (aetheria-api NOT api.aetheria)
  4. Docker Alpine + Prisma → Requires linux-musl-openssl-3.0.x binaryTarget
  5. Node 22 strict ESM → Use tsx not ts-node
  6. pnpm in Docker → Use pnpm fetch then pnpm install --offline
  7. Next.js NEXT_PUBLIC_* baked at build → Forward via docker-compose.prod.yml. After URL/env change, MUST rebuild web container: docker compose build web && docker compose up -d web
  8. Web proxy converts non-tRPC 429 to 500 → API must return tRPC envelope for /trpc/*
  9. CF rewrites X-Frame-Options → Assert both DENY/SAMEORIGIN
  10. Bot Fight Mode + Managed Challenge + custom Rate Limiting → ALL broke test suite, kept disabled
  11. Windows Credential Manager cache → Clear with cmdkey /delete:git:https://github.com
  12. Hetzner Console paste mangling → Type manually or use curl -L
  13. ENFORCE_CLOUDFLARE breaks web→API fetch → If Caddy doesn't forward cf-connecting-ip properly, web container's server-side fetch to API gets 403 CDN_REQUIRED. Either set ENFORCE_CLOUDFLARE=false or ensure Caddy header forwarding works (see /etc/caddy/Caddyfile cf_headers snippet).
  14. "fetch failed" on signup/login → Almost always wrong NEXT_PUBLIC_API_URL. Check it's https://aetheria-api.games-core.com NOT https://api.aetheria.games-core.com. After fix, MUST rebuild web container (env baked at build).
  15. Browser calls /api/auth/signup not /trpc/... → Next.js wraps tRPC calls in Next API routes (see apps/web/src/app/api/auth/*). These proxy to tRPC server-side. Don't debug as direct tRPC — check the Next route handler first.
  16. Docker env changes need full restart → docker compose restart api may not pick up new .env values. Use docker compose down && up -d with --env-file .env.prod for clean env reload.
